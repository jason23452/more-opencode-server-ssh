# 從提交補建專案脈絡

為既有專案建立可追溯的實作基線，讓後續 `grilling`／`grill-with-docs` 能快速了解已經做了什麼、目前能力與限制、哪些需求及理由仍需確認。輸出是歷史實作參照，不是事後替使用者核准的 spec，也不以 commit 訊息推定完整需求或驗收結果。

## 1. 確認整理範圍

- 讀取專案適用的 `AGENTS.md`；探索程式碼前遵循 domain 規範，讀取規格與票單前遵循 tracker 規範。缺少這些文件時，依專案現有文件與程式碼繼續，不要求先建立規格體系。
- 檢查 Git 狀態、目前分支、HEAD 與可用歷史。沿用使用者指定的 commits、分支、日期或功能範圍；未指定時預設整理目前 HEAD 可達的全部歷史，先盤點提交量與功能分布，再分批閱讀。未提交變更另列為工作區現況，不混入歷史成果。
- 將範圍固定為明確的提交清單與完整 SHA，記錄擷取時間、分支、基準及結束 SHA。日期篩選記錄時間欄位與時區；分支／區間說明端點是否包含。遇到來源歧義才透過 `question` 確認。淺層 clone、缺失物件或不可存取的歷史需列為缺漏，不自行 fetch 或切換分支。
- 搜尋 `session/` 中已涵蓋此範圍的筆記及其索引；重用有效參照，辨識新增、重疊與過時內容。首次補建沒有既有紀錄時直接繼續。

完成條件：提交範圍可重現、資料缺漏明確，且知道哪些功能與時段尚缺參照。

## 2. 重建歷史並核對現況

1. 先以 Git log 與檔案變更摘要盤點歷史，再依功能／模組閱讀相關 commit diff、當時檔案與目前實作。以使用者流程整理演進，避免只抄提交訊息或輸出逐筆流水帳。
2. 區分功能新增、行為調整、修復、移除、回退及整合。辨識 merge 與重複變更，避免將同一成果計算兩次；合併造成的實際差異另行核對。歷史中曾存在但目前已移除的能力標示為歷史能力。
3. 為各功能記錄用途、主要入口與檔案、資料／介面關係、可觀察行為、限制及相關 commits。每個重要結論附 SHA 與檔案參照，並區分「程式碼已核對」「提交訊息宣稱」「文件回報」「推測／待確認」。理由只有在來源明載時才列為歷史決策；從實作推導的可能動機列入訪談問題。
4. 有 spec、tickets 或領域文件時連結既有權威來源，核對其與實作是否一致；沒有時標記「無既有 spec／tickets」，不補造需求、票單或完成 checklist。
5. 驗證紀錄須附執行版本、指令、結果與來源。測試程式存在、commit 訊息寫著修復或功能已提交，都不代表測試通過、已部署或使用者驗收。預設不為歷史整理重跑整套測試；若另行驗證目前版本，將結果與歷史證據分開。

大型歷史按功能或時段分批，維護已讀／未讀提交範圍；未核對部分明列待整理，不能以抽樣宣稱全專案已涵蓋。

## 3. 寫入 session/ 快速參照

在專案根目錄建立 `session/`（不存在時建立），新增 `YYYY-MM-DD-commit-context-<主題>.md`。檔名衝突時使用唯一後綴，保留原紀錄；後續補建以新筆記連結舊基線，說明取代或修正的結論。

筆記依下列結構整理：

1. **快速摘要**：專案用途、目前主要能力、整理範圍及證據缺漏。
2. **來源與基準**：分支、完整 SHA／提交清單、時間範圍、查詢方式與工作區狀態。清單過長時另存相鄰 Markdown 附錄並連結。
3. **功能導覽表**：功能、目前狀態、程式碼入口、關鍵 commits、既有 spec／tickets（無則明列）、詳細段落連結。
4. **功能演進與現況**：按功能記錄重要修改、目前行為、相依關係、歷史決策依據與已移除能力。
5. **驗證與完成狀態**：可取得的測試／整合／部署證據及未知事項，各自標示來源與版本。
6. **後續訪談入口**：可延伸的既有功能、需要先核對的限制、缺少需求定義的部分，以及建議向使用者確認的問題；建議不視為已批准的工作。
7. **覆蓋與缺漏**：已核對、待整理的提交／功能與下一批入口。

建立或更新 `session/COMMIT-CONTEXT-INDEX.md`，用精簡表格記錄功能關鍵字、筆記連結、基準 SHA／範圍、核對狀態及後續筆記關係，供訪談快速定位。既有檔案若不是本 skill 的索引，先確認用途再整合，保留原內容。索引只保存摘要與指標，詳細事實留在筆記。

## 4. 銜接訪談與完成核對

- 在筆記標明：後續 `grilling`／`grill-with-docs` 先由索引定位相關功能，再讀詳細證據，並核對基準 SHA 之後的相關變更。筆記是歷史基線，不是目前狀態的永久保證。
- 既有 spec 可作為延伸候選；若歷史功能沒有 spec，後續訪談應以現況為基線建立第一份規格，清楚區分既有能力與本輪新增需求，不將既有程式全部當成待重做功能。需求歸屬與實作授權仍由訪談流程確認。
- 核對 SHA 可解析、專案內連結有效、重要結論有證據、缺漏已標示，並遮蔽機密值。只整理文件，不修改實作、不回填虛構歷史。
- 依專案文件提交規則詢問提交意願，列明本批筆記、附錄及索引；回報輸出路徑、實際涵蓋範圍、剩餘缺漏及提交狀態。

完成條件：後續 Agent 能由索引快速定位功能、追溯至提交與程式碼，辨識目前核對基線及未決問題；使用者要求的範圍均已整理，或明確回報未完成部分，不能把部分整理宣稱為完整專案基線。
