# Session 對話整理

將目前對話及其 subagent sessions 整理成繁體中文 Markdown 筆記，保存於目前專案根目錄的 `session/`。筆記應讓稍後回來的使用者或 Agent 能快速掌握背景並接續工作，不要逐字重播對話。

## 資料來源與輸出位置

- 整理來源是目前對話上下文：使用者訊息、Agent 回覆、工具結果、已提供的壓縮摘要，以及本次對話中可取得的 subagent 回報。
- `session/` 是筆記的輸出目錄，不是待整理對話的來源。預設直接整理上下文，不搜尋既有筆記、OpenCode session 儲存資料或 session metadata；只有使用者明確要求整理歷史紀錄或指定外部來源時，才讀取該範圍。
- 若部分對話內容不可見，以可見內容完成筆記並標明缺漏；不要求使用者先提供 `session/` 檔案，也不以尋找完整 session 記錄作為寫入前提。

## 步驟

1. 回顧目前 session，擷取目標、背景、已確認需求、重要決策及其理由、已完成工作、涉及檔案、驗證結果、未解問題與下一步。保留仍有效的細節，區分已確認事實、暫定想法與未決事項。
2. 若本次對話包含 subagent 回報或已提供的子對話內容，將其納入整理；沒有則略過。僅有回報摘要時，註明依據為摘要；已知但內容不可見的子 session 記為資料缺漏。
3. 整合主 session 與 subagent 的發現，去除重複內容，保留重要結論、決策、理由、執行成果及未完成事項；需要時標明由哪個 subagent 提供，以及是否已由檔案、規格、票單、提交或差異驗證。若 subagent 結論彼此不一致，保留分歧並標示待確認，不自行抹平。
4. 引用對話中已知的檔案、規格、票單、提交或差異，並保留已執行的驗證結果。保留對話或工具結果中已知的 commit hash，連同其對應變更或用途記入相關參照，方便後續追溯；hash 保留原樣，不自行推測或補造。只有具體事實需要核對時才讀取對應產物；未核對的內容標示為對話回報或待確認，不把推測寫成事實。
5. 在專案根目錄的 `session/` 建立 Markdown 檔。若目錄不存在則建立。使用 `YYYY-MM-DD-<簡短主題>.md` 作為檔名；若檔名已存在，改用不覆蓋既有內容的唯一檔名。
6. 檢查筆記涵蓋下列各節；沒有內容的項目寫「無」，不適用的項目可略過：

   - 摘要與目標
   - 背景與需求
   - 決策與理由
   - 已完成工作與變更檔案
   - 驗證結果
   - 未決問題／風險
   - 下一步（依優先順序）
   - 相關參照（專案內路徑、commit hash 與對應用途、連結）

7. 遮蔽 API key、密碼、token 等機密值；只記錄接續工作所需的資訊。完成後回報檔案路徑、整理範圍，以及已知的上下文缺漏。

## 完成條件

筆記已寫入 `session/`，內容涵蓋目前可見的對話上下文與相關 subagent 回報，可讓未讀取原對話的後續工作者辨識目前狀態、權威參照與明確的下一步；已知的上下文缺漏已標明，機密資訊已遮蔽。即使尚無 `session/` 目錄或既有筆記，也能直接完成整理與寫入。
