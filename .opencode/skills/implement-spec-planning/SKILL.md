# Implement-spec 排程與審查效率

本 skill 提供排程與 review 方法；交付、期限、授權與 worktree 規則以根目錄 `AGENTS.md` 為準。由 `implement-spec` 載入，也可用於單獨規劃；單獨規劃只輸出草案，不啟動實作或委派。

## 1. 沿用共同時間與確認輸入

- 使用者確認啟動本輪實作時，以系統時鐘記錄開始時間、時區及截止時間。其後的需求閱讀、探索、規劃與環境準備均計入總時限。
- 已有開始／截止時間時直接沿用；總時限已指定就直接採用。尚未指定時依 `AGENTS.md` 透過 `question` 請使用者自行輸入，不提供預設時長。
- 讀取 tracker 規範後確認 Spec、全部 tickets、驗收條件與依賴；探索程式碼前讀取 domain 規範。
- 確認工具實際支援的委派、並行、狀態查詢與取消能力，以及建置、測試與 worktree 成本。沒有可用 Subagent 時安排主 Agent 執行。

完成條件：所有 tickets 已列入，時間來源與可用資源明確；未知成本註明估計信心，不把推估當成保證。

## 2. 建立排程與 review 範圍

1. 為每張 ticket 標記前置依賴、修改範圍、驗收方式及具體風險。
2. 依關鍵路徑與可用資源安排時間窗；前置成果整合後才啟動依賴它的實作。獨立 tickets 可平行，共享檔案與資源的衝突須納入成本。
3. 依實際工具成本、歷史證據與複雜度估計時間，包括上下文載入、交接、合併與衝突修正。以重疊時間窗計算經過時間，不平均分配 tickets 或直接加總平行工時。
4. 預留整合測試、風險導向 review、修正、checklist、session notes 及回報時間；依風險決定配額，不套固定比例。
5. 為 review 指定需求符合度、適用規範與變更風險。權限、資料一致性、對外介面、錯誤處理等，只在變更涉及時納入。

輸出精簡計畫：

| Ticket | 前置依賴 | Agent／分支／worktree | 預計開始–完成／局部配額 | 驗收與 review 風險 |
|---|---|---|---|---|
| 各 ticket | 已整合的前置成果 | 實際可用資源 | 共同時間軸內的時間窗 | 測試與必查項目 |

另列共同開始／截止時間、關鍵路徑、整合驗證預留時間及主要不確定性。確認全部工作能排入共同期限；若有具體理由判斷不可行，依 `AGENTS.md` 先請使用者決策。

## 3. 實作時建立可重用的審查證據

在現有 ticket 或交接摘要維護下列資訊，避免另建重複的追蹤文件：

- 驗收條件與實作位置。
- 變更基準 SHA、已檢查的版本 SHA、檔案與檢查範圍。
- 實際執行的測試指令、結果及其覆蓋範圍；未執行的檢查明確標記。
- 已檢查風險、發現問題、修正狀態與仍待整合驗證的事項。

Ticket review 聚焦局部正確性。主 Agent 在整合時核對證據適用的版本與範圍；測試通過不能取代需求與風險審查，實作者宣稱完成也不能當作審查證據。

## 4. 執行風險導向整合 review

呼叫 `code-review`，明確指定 `implement-spec` 模式，提供：

- 整合分支建立時的基準 SHA、目前待審查 SHA、Spec／tickets 路徑。
- 共同截止時間、局部 review 配額，以及修正與驗證預留時間。
- 適用規範、變更檔案、既有審查／測試證據與尚未覆蓋的風險。

Standards 與 Spec 兩軸均須有覆蓋結果。已有有效證據的局部檢查可重用，整合 review 聚焦跨 ticket 介面、資料流、合併結果與尚未覆蓋的必要範圍。只有依據不足、版本或依賴變動時才重查受影響部分。

每項發現包含位置、需求／規範或失敗情境、影響與驗證方式，分為：

- **必修問題**：需求缺漏、行為錯誤、適用的硬性規範違反，或有具體證據的重大風險。修正並驗證後才可交付。
- **非阻擋建議**：沒有具體正確性影響的命名偏好、推測性 code smell 或範圍外重構。記錄即可，不擴大本輪實作。

修正後比對「上次已審查 SHA → 修正後 SHA」，複查問題及受影響的呼叫端、測試與整合範圍；只有修正產生新證據或擴大影響時才擴大 review。

完成條件：全部驗收條件有對應證據、兩軸必要範圍已覆蓋、必修問題已修正並驗證。達成就停止 review；無新變更或新證據時不再完整重跑。仍有必要檢查未完成時，標記未完成，不以配額用完視為通過。

## 5. 事件觸發的重新排程

在 ticket 啟動／完成、前置依賴整合、測試失敗、重大阻礙、衝突或進入最終驗證時讀取系統時間，更新剩餘工作與關鍵路徑。局部配額可調整，所有 agents 沿用共同截止時間；分派時交付相同的時間資訊、明確範圍與證據要求。

預測無法如期完成時，依 `AGENTS.md` 立即回報並透過 `question` 請使用者決策。等待回覆不自動暫停或延長期限。工具支援時依剩餘時間設定 timeout；prompt 無法保證取消執行中的呼叫，硬性中斷需由執行環境支援。

期限內的交付安排包含 session notes 與結果回報；合併 `dev` 的使用者等待及授權後清理另外處理，仍遵守 `AGENTS.md` 的授權規則。
