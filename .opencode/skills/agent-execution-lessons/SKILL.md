# Agent 執行經驗

以「成功解法快取」減少重複診斷：按需查、成功才寫、同題更新、有價值才工具化。本 skill 由目前 Agent 執行。

## 範圍與位置

- 涵蓋工具使用、命令、路徑、環境準備、派工與流程中的可重用執行教訓。產品功能 bug 連結診斷紀錄；修復、調整或搬移 skill 本身的問題不納入。
- 資料放在目前專案根目錄的 `agent-execution-lessons/`：`index.md` 為精簡索引、`<問題-id>.md` 為解法、`scripts/` 為必要的問題專用工具及測試。Git worktree 使用該 worktree 的專案根目錄；位置不明時先確認。
- skill 目錄只保存規則、[紀錄模板](references/lesson-template.md) 與通用工具。沒有值得記錄的解法時不建立目錄或空文件。
- 保留既有歷史文件與他人變更；舊 `incidents.md` 只按需作為診斷線索，不再新增事件或維護次數。既有 `pending` 紀錄不是已驗證解法，僅在本次問題涉及時重新核對，不批次遷移。

## 1. 按需查詢

遇到錯誤，或即將執行已知容易出錯的操作時，以錯誤特徵、工具與環境搜尋索引，只讀匹配紀錄；必要時搜尋資料目錄。同一輪已查過且條件未變，沿用結果。無資料或無匹配時直接進入診斷。

核對適用條件後才重用 `verified` 解法或工具；`pending`／`obsolete` 只作歷史線索。工具不取代既有專用工具或其權限，例如檔案修改仍使用 patch。

完成條件：已找到適用解法，或確認無匹配並繼續處理問題。

## 2. 先修復，再驗證

修復期間在目前對話保留必要的錯誤證據、假設與嘗試結果，區分事實與猜測，暫不寫入經驗庫。尚未定位的失敗依 `diagnosing-bugs` 處理；同樣失敗且沒有新證據時改變假設或拆解問題，再嘗試。

成功門檻必須全部滿足：

- 原本失敗的操作以修正方法執行成功。
- 實際輸出與任務後置條件符合預期；結束碼 `0` 或修改完成本身不算驗收。
- 受影響範圍的必要檢查通過，保留實際結果。

成功針對本次問題，不必等待整個專案完成。尚未成功而需交接時，只在 session note 記錄阻礙、已知事實與下一步。

例外：新證據推翻既有解法或其適用範圍時，立即在原紀錄與索引標示「適用性待確認」（`pending`）及失敗證據；確定失效時標為 `obsolete`。此更新只防止誤用，新修法仍須驗證成功才寫入。

## 3. 成功後選擇性寫入

先判斷重用價值：非直覺原因、容易再犯的限制或可重用修法值得記錄；單純筆誤與無重用資訊的一次性疏漏略過。取消發生次數門檻，一次成功解決即可沉澱。

- 已有適用解法且照做成功：不重寫、不增加計數。
- 新解法或新適用條件：依問題與環境匹配既有文件後更新；無匹配才建立穩定問題 ID，使用模板並加入索引。
- 僅記錄命中條件、原因、有效修法、驗證證據與預防方式。原因未確認就明示，不因方法成功而宣稱根因已證實。失敗嘗試只保留有助排除錯誤方向的部分。
- 驗證證據包含日期、實際環境、操作／檢查、結果及來源參照；來源依 `AGENTS.md` 的文件追溯規則記錄，先遮蔽機密。`verified` 只代表列明環境中的解法有效。
- 索引每題一列，保存問題 ID、查詢關鍵字、適用環境、狀態及文件連結；細節只在問題文件維護。
- 主／子 Agent 或跨 worktree 的同一解法依問題 ID 與來源證據去重；同一工作目錄指定單一寫入者，寫入前重讀相關文件，保留其他人的內容。

完成條件：有價值的新資訊已寫入且連結、狀態一致，或明確判定略過；無法寫入時回報阻礙，不宣稱已保存。核對本批文件後依專案規則詢問 commit，不為未改動的紀錄詢問提交。

## 4. 必要時才工具化

已驗證的修法若步驟重複、容易出錯且有實際重用需求，先找既有工具，再決定是否封裝。流程判斷保留文字規則，不預設每題建立腳本。

新增工具放在專案資料目錄的 `scripts/`，由問題文件連結。優先使用現有 Node.js／Python 環境與標準函式庫；參數、cwd、timeout、副作用及失敗回報須明確，子程序用參數陣列。避免 Shell 字串拼接與個人路徑，平台專屬功能標明適用條件。

驗證原問題的修復行為、無效輸入與失敗回報；涉及路徑／參數時包含空白、引號與 Unicode。工具驗證通過後才加入可重用入口；未完成時保留已驗證的原修法，工具待辦留在交接筆記。

## 整理模式：由 session-notes 呼叫

1. 只使用提供的對話與筆記，找出已成功解決且有重用價值的執行問題；依第 3 節補查是否漏記新資訊，不重建事件流水帳或計次。
2. 未解決問題留在 session note；既有解法遭反證時依第 2 節標示限制。歷史不可見時不補造原因或驗證結果。
3. 僅在符合第 4 節條件時工具化，核對本批文件的內容、狀態與連結。
4. 回傳新增／更新路徑、驗證結果及阻礙，由 `session-notes` 統一處理提交詢問。沒有新資訊時回報「無新增執行經驗」，不建立空紀錄，也不遞迴呼叫 `session-notes`。
