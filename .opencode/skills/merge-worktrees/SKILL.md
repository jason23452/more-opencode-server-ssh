# 選擇並合併 worktrees

本 skill 由使用者另行呼叫，開發收尾只交付報告，不自動進入本流程。遵循根目錄 `AGENTS.md`；讀取票單前先讀 tracker 規範。

## 1. 盤點與報告

1. 使用 Git worktree 清單辨識目前 repo 的工作目錄、分支與 HEAD，定位 `dev` 及其保留工作目錄。不存在或有歧義時透過 `question` 確認。保留其他工作區及暫存區變更。
2. 讀取各來源 worktree 的 `pr/` 報告，並以來源分支中的已提交版本核對；不能只搜尋目前分支的 `pr/`，因為待合併報告尚未進入 `dev`。以來源分支及批次識別去重，核對報告來源與實際分支是否一致。
3. 列出報告路徑、交付摘要、來源分支／worktree、成果 SHA、當前 HEAD、驗證狀態、依賴及阻礙。以 Git 祖先關係核對是否已合併；報告未提交、工作區不乾淨、證據失效或缺少必要驗收者列為受阻。沒有報告的 worktree 列為缺少證據，不自行假定已完成。
4. 核對成果 SHA 後的差異；僅已核對的交付文件可沿用驗證。程式、設定或驗收範圍變動須先補驗並更新報告。已經合併者不列入待合併選項，清理待辦另列。

## 2. 使用者選擇

透過 `question` 的 `multiple: true` 列出可合併項目，每個選項對應單一來源分支，描述附報告、摘要及依賴；提供「本輪不合併」選項，若與其他選項同選則再確認。無可選項時回報阻礙並停止。

選擇只授權列出的分支及當時 HEAD。相依分支未選且尚未進入 `dev` 時，透過 `question` 請使用者補選或取消相依項目，不暗中擴大範圍。記錄選定 SHA 與順序，依依賴拓樸排序；未選成果保留。

使用者明確要求延後特定驗收時，列明待補項目及影響後才將該來源納入選項；一般多選不代表豁免驗收。合併後標記「已合併／驗收待補」，保留來源至必要驗證補齊。

## 3. 串行合併與驗證

1. 每次合併前重新核對來源 HEAD、目標 `dev` 與乾淨狀態。來源 HEAD 改變時重新呈現差異並取得選擇授權；目標變更時重評相容性與必要驗證。
2. 在乾淨的 `dev` worktree 串行合併選定 SHA，以保留來源祖先關係的合併方式留下追溯證據。每項完成後記錄合併 SHA，針對合併後實際版本執行必要整合檢查；先前單獨通過不代表組合後已驗證。
3. 衝突或驗證失敗時停止相依項目，不強行解衝突、不自動重設或刪除成果。記錄目前 Git 狀態；未完成的 merge 依可安全還原的前提中止，否則保留並回報。已落入 `dev` 但驗證失敗者明記「已合併／驗證受阻」，保留來源，取得修正或回復決策後再繼續。程式修正委派給 subagent，必要時依專案規則取得主 Agent 接手同意。

## 4. 紀錄與清理

本輪合併與驗證結束或因阻礙停止後，才在 `dev` 更新同一份 `pr/` 報告及對應既有 session note，避免中途文件修改使下一項合併的目標工作區變髒。記錄選定來源 SHA、合併 SHA、驗證結果及清理狀態。尚未合併的受阻報告更新於其保留來源，分別列出提交範圍。文件提交依 `AGENTS.md` 另行取得同意；合併選擇不等於文件提交授權。

核對成功合併且驗證通過後，僅停止本批服務並清理已保存、乾淨且已整合的 ticket／integration worktrees 及其分支。若目前 session 位於待刪除目錄，先移至保留主工作目錄。核對 Git worktree 清單、實體目錄與分支清單，再將最終清理結果補入同份報告與 session note，一併核對及詢問提交。未選、受阻、未保存或驗證失敗的來源繼續保留；`dev` 及其工作目錄保留。

回報每項合併、驗證、文件提交與清理結果，附 SHA 和剩餘阻礙。部分成功不等於全部成功，合併也不代表整份 spec 已完成。
