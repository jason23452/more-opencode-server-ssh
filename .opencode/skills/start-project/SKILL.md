# 啟動專案

目標是讓使用者能實際使用目前專案，並能自行重現啟動與停止流程。所有專案路徑均以使用者指定的專案根目錄為基準；未指定時使用目前工作目錄。

## 1. 確認啟動入口

- 先閱讀適用的 `AGENTS.md` 與其要求的前置文件，再依需要閱讀 README、開發指南、工作區設定、依賴清單與鎖定檔、任務腳本、容器或服務配置、環境變數範本。
- 以專案現有的啟動入口與版本設定為依據，辨識所需 runtime、套件管理器、建置工具及服務。技術可能混用；依賴檔的存在本身不代表它就是啟動入口。
- 預設啟動本機開發環境與完成主要使用流程所需的服務。若有多個彼此獨立的應用且無法由上下文判定目標，透過 `question` 確認；已有明確預設時直接執行。
- 使用者只要求手動教學時，完成入口與前置條件查核後直接提供步驟，明確標示未實際啟動；其他啟動要求須繼續執行。

完成條件：掌握目標應用、各服務的工作目錄、相依順序、啟動命令與可用的就緒檢查方式。無可執行入口時回報具體缺口，不憑空生成啟動命令。

## 2. 準備環境

- 核對本機工具與版本、依賴安裝狀態、必要環境變數及外部服務。依既有鎖定檔與專案指令補齊依賴，優先使用專案範圍的環境。
- 依範本建立缺少的本機設定，保留使用者既有值。必要憑證缺少時指出變數名稱與設定位置，請使用者在本機填入；回報及指令範例使用佔位符。
- 按專案文件執行必要的本機初始化或 migration；先確認其目標環境。會清除既有資料的重建、重設或 seed 覆寫，須先取得明確同意。
- 檢查所需 port 與既有服務歸屬。符合本專案與配置且健康的既有服務可沿用；遇到其他服務占用時，以本機覆寫或啟動參數分配可用 port，並同步相關 URL、代理、CORS 與連線設定。多 worktree 時遵循專案的統一 port 配置規則。
- 需要安裝系統工具、外部帳號或使用者操作才能繼續時，列出具體阻礙與最短補齊步驟；能獨立完成的準備繼續進行。

完成條件：必要工具、設定與相依服務可用，或已辨識明確阻礙及其影響範圍。

## 3. 啟動並驗證

- 按依賴順序啟動，優先使用專案既有的統一啟動命令。長駐程序使用可跨工具呼叫持續運作的背景執行方式，避免以前景工具逾時管理服務生命週期。
- 記錄本次啟動的工作目錄、命令、非機密環境設定、程序／容器識別與日誌位置；區分新啟動及沿用的服務，以便精準停止。
- 給予合理啟動時間並設定就緒等待上限，檢查日誌、程序／容器狀態及實際監聽位置，再使用專案提供的健康檢查或最小操作確認可用。Web 專案檢查實際頁面與必要 API；CLI、桌面程式、worker 或其他類型採其適用的最小操作與結果驗證。
- 檢查應對應本次目標實例；只有程序存在、編譯成功或輸出啟動訊息，不足以宣稱可用。無法驗證 GUI 或外部整合時，分別標示已驗證部分與待人工確認部分。
- 啟動失敗時，依錯誤與日誌定位原因；有 `diagnosing-bugs` 等適用診斷流程時按需載入。修正啟動配置後重試受影響部分，相同失敗且沒有新證據時改變假設或回報阻礙。

完成條件：目標實例通過適用的就緒與最小操作驗證，或已保存失敗證據、指出阻礙及仍在運作的服務。成功啟動後保留服務供使用者操作。

## 4. 交付手動操作方式

最終回覆依實際環境提供以下資訊，命令必須符合使用者的作業系統與 shell：

1. **目前狀態**：已啟動、沿用、部分啟動或受阻；列出實際存取網址或應用入口，以及驗證結果。
2. **首次準備**：必要工具與版本、依賴安裝、環境檔來源及必要初始化。區分首次準備與每次啟動。
3. **手動啟動**：按順序提供可複製的命令、執行目錄與必要環境設定。多個前景服務分別標示終端機；以本次實際成功的方式為依據，尚未驗證的命令明確註記。
4. **確認成功**：預期畫面、健康檢查或最小操作，以及實際 port 與日誌查看方式。
5. **停止與重啟**：手動前景執行的停止方式、本次背景程序／容器的精準停止命令，以及再次啟動步驟。停止範圍僅涵蓋本次建立的服務；沿用的服務標示其歸屬。

手動步驟須說明本次服務仍在運作時可直接使用，若要自行重跑則先依停止步驟處理，避免重複啟動。若使用了本機覆寫或非預設 port，步驟須包含重現方式。

教學預設直接回覆使用者；要求寫入文件時才更新專案文件，並遵循專案的文件核對與提交規範。
