# 多 Agent 蒐證與方案比較

本流程供 `grilling` 及其入口共用，在技術方案定案前執行。目標是找出符合使用者條件且能驗收的實作方案。

## 1. 確認決策條件

透過 `question` 確認交付平台、必要功能、驗收層級、時間與預算限制，以及成本、速度、完整度、維護性的優先順序。只詢問尚未確定的決策；檔案、工具與環境事實由 Agent 查證。

區分「可寫程式」「可建置」「可在目標環境運行驗收」「可發布」。例如 App 須確認 Android／iOS、模擬器／實機及是否上架，再判定所需設備、SDK、簽章與帳號，避免把開發能力當成交付能力。

完成條件：研究目標、硬性限制與比較優先順序明確；尚未回答的條件以未知標示，只啟動不依賴它們的調查。

## 2. 多 Agent 蒐證

首次技術方案調查預設分派下列四個唯讀職責。前三項在前置條件具備時平行執行；方案比較職責取得初步證據後啟動，避免憑空推定可行性。

| 職責 | 調查與交付 |
| --- | --- |
| 歷史與重用 | 依主技能的歷史流程，搜尋 spec、tickets、session、Git 與目前實作，核對可重用能力、過去失敗及尚未完成的依賴，回報路徑與 SHA。 |
| 現況與環境 | 核對作業系統、工具與版本、SDK、設備、服務、權限及可存取的遠端環境；對照建置、運行、驗收、發布逐層列出缺口與檢查證據。 |
| 網路與官方資料 | 使用網路搜尋定位候選方案，再閱讀官方文件、版本說明、平台相容性與價格資料；保留 URL、查詢日期及適用版本。第三方經驗僅作線索，重要結論回到一手來源核對。 |
| 方案比較與驗證設計 | 根據前三項證據比較候選方案，檢查隱藏依賴與反例，提出可推翻關鍵假設的最小實驗、成功條件與所需資源。 |

- 主 Agent 派工須提供目標、限制、已知證據、搜尋範圍、前置結果與輸出要求；各職責區分「已查證事實、推論、未知」，指出證據適用範圍。獨立工作並行，有依賴的工作等待必要結果。
- 沒有 repo 時，歷史職責記錄無本機歷史可查；使用者提及但無法存取的專案標記存取缺口。相關職責無調查對象時說明理由，可合併職責，但有多項獨立調查時須實際使用多個 subagents。
- 工具並行上限不足時分批；無委派或網路工具時回報未完成的調查與影響，透過 `question` 確認改由主 Agent 調查或由使用者補充資料。僅暫停依賴缺失證據的決策，不宣稱已完成多 Agent／網路查證。
- 新一輪只補查新增或失效的部分，沿用仍有效的來源與結果；研究期間繼續詢問不依賴調查結果的問題。

完成條件：各適用職責已回報可追溯證據或具體阻礙，主 Agent 已核對影響推薦的關鍵結論與矛盾。僅收到摘要而未獨立核對的內容標記「依回報摘要，未獨立核對」，不足以單獨確認關鍵可行性。

## 3. 整合替代方案

主 Agent 依硬性限制篩選方案，依使用者優先順序推薦，不以搜尋排名或票數決定「最佳」。結果有衝突時核對版本、日期與適用條件；無法消除的差異列為待驗證。

目前方案受阻時，先說明受阻範圍與證據，再調查補齊環境、改用其他執行方式、調整本輪交付範圍等可行路徑。通常提供二至三個有實質差異的方案；只有一個或沒有可行方案時如實說明，不湊選項。未查證方案標記為候選，不能承諾交付。

每個方案須比較：

- 可達成的目標、與原始需求的差異，以及延後或犧牲的能力。
- 所需環境與外部依賴；哪些已具備、哪些需建置、哪些尚未確認。
- Agent 可處理的工作，以及使用者需提供的設備、帳號存取、服務、預算或人工操作；逐項說明用途、負責人、最晚需要時點與未提供的影響。敏感憑證透過適當的環境設定提供，不寫入研究文件。
- 成本、交付時間與維護負擔；估算列依據與未知，不當作保證。
- 建置、運行及驗收方式、可覆蓋與不可覆蓋的範圍、來源與關鍵前提。

例如缺少本機 iOS 建置環境時，可調查遠端 Mac、支援該專案的雲端建置，或先交付 Web／PWA。各自確認簽章、裝置與驗收條件；Web／PWA 屬交付範圍變更，須由使用者明確選擇。

## 4. 驗證、決策與交接

文件證據不足時提出最小實驗：要驗證的假設、操作、成功／失敗判準、耗時及所需資源。唯讀研究不包含安裝、付費、建立資源或修改專案；依目前模式與授權確認後才執行實驗，Plan mode 僅提出方案。實驗尚未執行時保留待驗證狀態。

透過 `question` 呈現推薦及取捨，讓使用者選擇補齊資源、採替代方案、調整範圍或暫緩。確認可行性關鍵前提的處置後，再更新交付範圍與驗收；使用者接受風險不等於未知已驗證，也不自動授權開始實作。

交接摘要包含選定及淘汰方案的理由、來源、環境缺口、資源責任、驗證結果與未決事項。純討論直接在對話摘要；需要產出文件時依主技能及文件提交規則處理，文件以職責名稱追溯，不記錄工具 session ID。

完成條件：使用者已確認方案與重要取捨，關鍵前提已有證據或明確的待驗證處置；仍受阻的交付保持待確認，不以編譯或 mock 成功替代目標環境驗收。
