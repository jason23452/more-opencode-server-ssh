# sshdeck 第一版設計共識

狀態：使用者已確認。本文記錄需求訪談結果，作為後續規格與實作依據；尚未實作。

## 目標與環境

建立個人使用的本機 CLI 工具 `sshdeck`，可以開啟瀏覽器管理介面，並透過本機 Node.js 程式連接 SSH 主機。CLI 與前端皆可管理主機、金鑰及執行遠端工作。

- 本機支援 Windows、macOS、Linux，提供一致的主要功能。
- 遠端受管主機為 Linux，Docker 已安裝。
- 使用直接 SSH 連線，包含本機透過既有 VPN 可達的主機。
- 第一版以有人操作的互動情境為主。
- 領域用語見根目錄 `GLOSSARY.md`。

## 主機管理與命令入口

可動態新增、修改、刪除多組主機連線設定。每組設定包含唯一主機別名、位址、SSH 連接埠、登入帳號與登入金鑰關聯。同一台實體主機可用不同別名對應不同登入帳號。

主機列表顯示保存的設定及連線檢查結果，不將先前檢查成功視為目前仍保持連線。使用者可以在不同主機同時操作，每次操作均指定單一目標；第一版不要求一鍵批次執行。

已確認的指令結構：

```text
sshdeck ui
sshdeck host add dev
sshdeck host list
sshdeck host check dev
sshdeck exec dev -- docker ps
sshdeck exec dev -- docker start app
sshdeck shell dev
sshdeck key create dev
sshdeck guide dev
```

- `ui`：啟動本機管理服務並開啟瀏覽器。
- `host`：管理主機設定及檢查連線；修改、刪除等詳細參數於後續規格定義。
- `exec`：依別名執行遠端命令，即時呈現輸出及結束狀態。
- `shell`：依別名開啟完整互動終端機。
- `key`：建立及管理登入金鑰。
- `guide`：顯示公鑰安裝及登入帳號權限指南。

前端提供相對應的主機與金鑰管理、檢查、命令執行及互動終端機功能。Docker 操作使用通用遠端命令與終端機，不要求專用容器管理介面。

## 金鑰、授權與主機身分

- 支援新建金鑰與選用本機既有私鑰。
- 新建金鑰預設為每組主機連線設定建立獨立、帶密語的 Ed25519 金鑰；亦可手動選用既有金鑰。
- 私鑰留在本機，公鑰授權給遠端登入帳號。
- 工具提供可複製的公鑰及安裝指令，使用者透過既有登入方式或主機控制台套用，再由工具驗證連線。
- 指南涵蓋登入帳號建立、公鑰加入 `authorized_keys`、相關檔案擁有者與權限設定。
- 首次連線顯示主機指紋，由使用者核對並信任；後續指紋改變時停止連線，需重新確認。
- CLI 與前端共用主機信任紀錄。

## Docker 帳號權限

受管主機上的登入帳號是使用者信任的管理帳號。指南採一般 Docker Engine 與 `docker` 群組授權，該權限具有主機高權限的影響，並非僅能管理個人容器。

工具提供管理員可執行的帳號及群組配置指令，由使用者自行套用，不直接代為修改遠端權限。工具檢查 SSH 登入與該登入帳號能否操作 Docker；具體檢查方式於後續規格定義。第一版不涵蓋 Docker 安裝流程。

## 解鎖與資料保存

- CLI 每次操作需要時輸入私鑰密語。
- 前端在本機服務執行期間暫存解鎖狀態，提供手動鎖定，服務停止即清除。
- 密語不持久保存。
- 主機設定、信任指紋及工具建立的金鑰存放於各平台的使用者應用資料目錄，CLI 與前端共用。
- 選用既有私鑰時只保存其檔案位置。
- 刪除主機設定不自動刪除金鑰，也不自動撤銷遠端公鑰授權；金鑰刪除與遠端撤銷須有獨立操作或指南。

## 終端機生命週期

CLI 與前端都提供完整互動 shell，支援需要終端機輸入的操作。執行命令或開啟終端機時才建立所需 SSH 連線。

關閉終端機即結束該 SSH 工作階段；斷線後可重新開啟新工作階段，不恢復原終端機。持續運行的容器可使用 `docker run -d`；一般遠端程序是否在斷線後繼續運行取決於遠端程序本身。
