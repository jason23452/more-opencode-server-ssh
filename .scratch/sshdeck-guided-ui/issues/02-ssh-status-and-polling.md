# 02 — 實作 SSH 三色狀態與定期檢查

Status: ready-for-agent
Type: task
Blocked by: 01
Spec: [SSH 主機操作介面與逐步建立指南](../spec.md)

## 目標與範圍

在主機列表提供可理解且附時間的 SSH 連線檢查結果，提供指南可重用的檢查與錯誤分類能力。沿用既有主機檢查／解鎖／指紋確認 API，區分自動檢查與使用者主動操作。

- 綠：最近檢查成功；紅：已執行且失敗；灰：未知、未設定完成、需解鎖或需確認指紋。
- 頁面可見時每 30 秒檢查符合條件的主機；隱藏暫停，返回更新。
- 同主機的手動與自動檢查共用去重控制；限制未完成請求累積。
- 舊回應需核對主機與連線設定是否仍有效；暴露設定失效處理供 05、06 使用。

## 驗收條件

- [ ] 三色狀態符合 spec，搭配原因與檢查時間，不使用顏色作唯一資訊。
- [ ] 檢查中有回饋，不先宣告成功或失敗；歷史結果不宣稱即時在線。
- [ ] 可見時每 30 秒檢查，隱藏時停止新排程，恢復可見時更新，提供立即檢查。
- [ ] 同主機檢查不重疊，失敗後可重試，輪詢不無限制累積請求或連線。
- [ ] 自動檢查需解鎖或指紋確認時顯示灰燈及處理入口，不反覆彈窗或自動信任。
- [ ] 使用者主動操作可完成解鎖與指紋確認，沿用既有驗證規則。
- [ ] SSH 與 Docker 結果分離，Docker 失敗不使 SSH 成功轉紅；記錄定期 Docker 檢查成本的處理方式。
- [ ] 刪除或修改主機後，舊檢查回應不能覆蓋新狀態；輪詢不清空表單或重建終端機。

## 驗證

以可控制時間與回應的測試驗證輪詢、可見性、去重、延遲回應及各狀態；覆蓋 SSH 成功但 Docker 不可用、解鎖與指紋分支。與真實 UI 整合後確認回饋與重試入口。
