## 驗收條件

- [ ] 完成首次新增 → 金鑰 → 手動授權 → SSH 檢查成功 → 前往目標主機 → 主動開啟終端機的端到端驗證。
- [ ] 驗證既有金鑰、檢查失敗後修正、解鎖與指紋確認，以及 SSH 成功但 Docker 不可用。
- [ ] 驗證指南各關鍵階段重新整理、每台主機進度與未建立草稿接續，確認無重複主機或金鑰。
- [ ] 驗證 A 至 B 切換確認／取消、切分頁保留終端、延遲回應隔離及輪詢不干擾輸入／輸出。
- [ ] 驗證設定／金鑰變更與主機刪除後，燈號、指南進度、選取及終端狀態一致。
- [ ] 完成人工桌面／窄螢幕、鍵盤、長指令、文字與顏色提示、操作位置與複製回饋檢查。
- [ ] 既有 SSH、金鑰管理、單次命令與 Docker 的相關回歸檢查通過。
- [ ] 風險導向審查涵蓋需求符合度、敏感資訊保存、指紋信任、請求累積與跨主機輸入／輸出；發現的問題已修正及驗證。
- [ ] 每項 spec 驗收條件均能對應票單與驗證證據；只有已實作且驗證通過的項目勾選，阻礙與未完成項目明確記錄。
