# 04 — 建立四步 SSH 指南與錯誤導引

Status: ready-for-agent
Type: task
Blocked by: 01, 02
Spec: [SSH 主機操作介面與逐步建立指南](../spec.md)

## 目標與範圍

為 SSH 新手提供「連線資料 → 登入金鑰 → 遠端授權 → 檢查連線」的逐步精靈。沿用現有主機、金鑰與指南 API，以及 02 的檢查能力。本票負責當次頁面的步驟狀態，重新整理後恢復由 05 處理。

## 驗收條件

- [x] 一次以一步為主，顯示進度、上一步／下一步、目的、操作位置、範例及預期結果，往返不丟失仍有效的資料。
- [x] 連線資料收集別名、位址、埠與登入帳號；缺少資料、格式與別名衝突有就地修正資訊。
- [x] 說明需既有控制台或 SSH 登入管道，沒有管道者能找到取得控制台或請管理者協助的指引。
- [x] 預設建立新金鑰並確認密語；既有金鑰方式可展開，說明路徑位於執行 sshdeck 的電腦。
- [x] 區分公鑰、私鑰與密語；密語不進授權指令、前端持久儲存或錯誤詳細資訊。
- [x] 授權步驟依目前主機與帳號顯示公鑰及指令，標記在遠端執行、Linux 適用環境與管理者權限需求。
- [x] 指令有複製成功回饋，長指令不撐寬頁面，授權操作保留既有公鑰。
- [x] 手動完成授權只允許進入檢查，不直接宣告成功；「檢查連線」顯示檢查中狀態。
- [x] 解鎖及指紋確認使用既有主動 `services.checkHost` 流程，SSH 成功即可完成，Docker 不可用不阻擋。
- [x] 成功後點「前往主機操作」選中對應主機但不自動連線；選取沿用 03 的切換確認 hook。
- [x] 失敗保留資料與步驟，提供白話原因、修正入口與可展開技術資訊；依錯誤碼／訊息區分不可達、認證失敗、需解鎖、指紋未確認／變更及未知錯誤。
- [x] 主流程不混入 Docker 與撤銷授權長篇內容。

驗證新金鑰與既有金鑰兩條路徑、前後步驟往返、錯誤修正重試、SSH 成功但 Docker 失敗、複製回饋與敏感資訊遮蔽。03 尚未整合時可驗證導向事件，完整跨主機切換由 07 確認。
