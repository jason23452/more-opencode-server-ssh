# SSH 主機操作介面與逐步建立指南

## 文件狀態

需求已確認：主要流程與四項補充決策已由使用者確認，實作票單見下方索引。尚未開始實作。

## 問題與目標

目前介面把主機管理、金鑰、授權指令、撤銷授權與 Docker 說明集中呈現。即使開發者也難以判斷下一步，以及指令應在哪台電腦執行。

主要使用者是已擁有遠端主機，但不熟悉 SSH 金鑰與授權的人。目標是讓使用者依逐步指南完成 SSH 連線檢查，再從明確的主機操作頁進行互動操作。

成功的判準：使用者按下「檢查連線」後 SSH 檢查成功；不以開啟終端機或 Docker 可用作為建立指南的完成條件。

## 術語與現況

沿用根目錄 `GLOSSARY.md` 的受管主機、主機別名、登入帳號、登入金鑰、主機指紋、SSH 連線檢查、終端連線與建立指南。

- SSH 連線檢查代表檢查當時可連入，不等於持續保持終端連線。
- 現有 UI 位於 `bin/sshdeck.js`，以內嵌 HTML 與 JavaScript 提供。
- 現有系統具備主機管理、登入金鑰管理、SSH／Docker 檢查、單次遠端命令與互動式終端機。
- 現有主機列表顯示最近檢查結果，尚非定期更新的在線資訊。
- 現有授權指南產生手動指令，不會自動登入遠端建立帳號或安裝公鑰。

## 主機操作

### 列表與選取

- 顯示所有已加入的受管主機，包括未完成設定與目前無法連線者。
- 每筆顯示主機別名、必要連線資訊、SSH 檢查燈號、文字原因與最近檢查時間。
- 無主機時顯示前往建立指南的入口。
- 選取主機後，在下方顯示其操作區；選取本身不自動開啟終端連線。
- 提供「連線」「中斷」及「立即檢查」等明確操作。

### SSH 檢查狀態

| 燈號 | 意義 | 顯示要求 |
| --- | --- | --- |
| 綠 | 最近一次 SSH 檢查成功 | 顯示成功與檢查時間，不宣稱終端機已連線 |
| 紅 | 已執行檢查且失敗，例如連線逾時或認證失敗 | 顯示白話原因與修正入口 |
| 灰 | 未知、尚未檢查、設定未完成、需要解鎖或確認主機指紋 | 顯示需要完成的下一個動作 |

- 終端連線狀態獨立顯示，例如未連線、連線中、已連線、已中斷。
- 頁面可見時，每 30 秒更新具備檢查條件的受管主機；頁面隱藏時暫停，重新可見時更新。
- 提供手動立即檢查；同一主機已有檢查進行時不重複發送。
- 檢查進行中顯示進度，不把尚未完成的檢查當作成功或失敗。
- 自動檢查遇到解鎖或主機指紋確認需求時，顯示灰燈與入口，不反覆彈出互動視窗，也不自動信任指紋。
- 歷史結果須附時間；暫停更新期間不可呈現為即時在線保證。
- Docker 結果與 SSH 結果分開，Docker 不可用不使 SSH 成功變成失敗。

### 終端連線生命週期

- 本次採單一選定主機的互動終端機；從 A 切到 B 時中斷 A 的終端連線。
- 切換後不得把 A 的輸出或延遲回應呈現在 B 的終端機，輸入也不得送至錯誤主機。
- 使用者須主動開始 B 的終端連線。
- 中斷終端連線不應被描述為保證停止遠端所有程序。
- 有活躍終端連線時，切換主機前提示將中斷並允許取消；確認後才中斷及切換。只切換左側分頁時保留同一主機的終端連線。

## 建立指南

### 共通呈現

- 採逐步精靈，一次以一個步驟為主；顯示步驟名稱、目前進度、上一步與下一步。
- 每一步說明目的、操作位置、輸入範例與完成後的預期結果。
- 指令提供複製按鈕與複製成功回饋；長指令在區塊內捲動，不撐寬整個頁面。
- 額外解釋可展開；主要流程不一次展示撤銷授權與 Docker 指令。
- 不要求使用者重新輸入前一步已提供且仍有效的資料。

### 步驟一：連線資料

- 收集主機別名、主機位址、SSH 連接埠、登入帳號。
- 清楚解釋欄位，並就缺少資料、格式錯誤與別名衝突提供就地修正資訊。
- 說明使用者需要已有方式進入遠端主機，例如主機商網頁控制台或既有 SSH 登入方式。
- 沒有既有登入管道者，提供取得控制台或請管理者協助的指引，不假設尚未授權的金鑰已可登入。

### 步驟二：登入金鑰

- 預設引導建立新登入金鑰；沿用現有金鑰密語與確認機制。
- 已有金鑰者可展開其他方式，沿用既有金鑰關聯能力。
- 解釋公鑰供遠端授權、私鑰與密語不應貼到遠端授權指令。
- 既有金鑰路徑要說明是執行 sshdeck 的電腦上的路徑，避免誤認為瀏覽器所在電腦或遠端主機的路徑。

### 步驟三：遠端授權

- 明確標記「在目標受管主機的控制台或既有 SSH 視窗執行」。
- 依目前主機與登入帳號提供授權指令、複製公鑰與預期結果。
- 沿用現有手動授權方式，保留遠端既有公鑰，不因簡化介面改成覆蓋授權檔。
- 區分需要管理者權限的操作與一般登入操作；無權限時提供請管理者協助的說明。
- 使用者表示已完成手動操作，只代表可進入檢查步驟，不等於系統已驗證授權成功。
- 現有指令涉及 Linux 工具；教學須清楚標示適用環境，不宣稱可直接套用到所有作業系統。

### 步驟四：檢查連線

- 提供明確的「檢查連線」按鈕及檢查中回饋。
- 需要解鎖或確認主機指紋時，從使用者操作流程引導完成，不跳過既有驗證。
- SSH 成功即顯示指南完成；Docker 結果不阻擋完成。
- 成功後提供「前往主機操作」，點擊後選中對應主機，不自動開啟終端機。
- 失敗停留在本步，保留資料與進度；顯示白話原因、建議下一步及回到對應設定步驟的入口。
- 原始技術錯誤放在可展開的詳細資訊；不得暴露密語或私鑰。
- 至少區分無法到達主機、認證失敗、需要解鎖、主機指紋尚未確認／已變更，以及未知錯誤。

## 進度保存與資料一致性

- 切換分頁及重新整理後，能接續原受管主機的設定步驟與非敏感輸入。
- 不把密語、私鑰或解鎖憑證寫入前端持久儲存。
- 恢復時核對現有主機與金鑰狀態，避免重複建立主機、重複產生金鑰或顯示不存在的設定成果。
- 更改連線資料、登入帳號或登入金鑰後，先前檢查成功不能直接代表新設定成功；須重新檢查。
- 恢復的歷史成功結果須附檢查時間，不當作當前終端連線。
- 進度限定同一瀏覽器保存；每台已加入主機可接續，另保留一筆尚未建立主機的草稿，不要求跨瀏覽器同步。

## 進階管理

從選定主機的進階入口存取 Docker 檢查與權限指南、撤銷公鑰指南、單次遠端命令，以及既有主機／金鑰管理能力。

主機編輯、刪除、檢視公鑰、刪除受管理金鑰與解除既有金鑰關聯仍須有可找到的入口。維持本機金鑰刪除、解除關聯與遠端撤銷授權的區別。

## 實作邊界與整合風險

- 優先沿用現有主機、金鑰、指南、檢查、遠端命令與 shell API；不以全面改寫後端為前提。
- 現有檢查介面同時取得 SSH 與 Docker 結果；定期檢查的實作需評估重複 Docker 檢查的成本，但 UI 的 SSH 成功判定必須獨立。
- 更新列表或輪詢結果不得重建仍在使用的終端機、覆蓋使用者輸入或切換選取目標。
- 主機刪除、設定修改與切換造成的延遲回應，必須核對目標與設定版本後才能更新狀態。
- 輪詢不得無限制累積連線或請求；錯誤後仍能由使用者重試。
- 本次不要求導入特定前端框架。

## 驗收條件

- [ ] 左側有依序排列的「主機操作」「建立指南」，且無主機時可直接開始指南。
- [ ] 所有受管主機均可選取，選取後下方明顯顯示操作目標與互動終端機。
- [ ] 綠／紅／灰燈與文字符合本文定義，附檢查時間，與終端連線狀態分開。
- [ ] 可見頁面每 30 秒更新符合條件的主機；隱藏時暫停，返回後更新，支援立即檢查且不重複發送同主機檢查。
- [ ] 自動檢查遇到解鎖與指紋問題時不反覆彈窗或自動信任。
- [ ] 切換 A 至 B 會中斷 A，B 需主動連線，輸入與輸出不會跨主機混用。
- [ ] 指南依四個步驟引導，提供操作位置、複製按鈕及預期結果。
- [ ] 新金鑰為預設流程，既有金鑰入口可展開，金鑰路徑的所在電腦清楚可辨。
- [ ] 遠端授權教學保留既有公鑰，並標示適用環境及必要權限。
- [ ] 按下檢查後 SSH 成功即可完成，Docker 失敗不阻擋，並能前往對應主機操作頁。
- [ ] 檢查失敗有白話原因、修正入口與可展開的技術資訊，且保留已輸入內容。
- [ ] 切換分頁或重新整理後可接續非敏感設定進度，且不因恢復而重複建立主機或金鑰。
- [ ] 修改連線設定或金鑰後會要求重新檢查，歷史成功不冒充新設定的成功。
- [ ] Docker、撤銷授權與單次命令位於進階入口；既有主機與金鑰管理操作仍可使用。
- [ ] 狀態不單靠顏色辨識，主要操作可用鍵盤完成，長指令不造成整頁橫向溢出。

## 驗證規劃

- 狀態與流程測試：三色映射、SSH 與 Docker 分離、指南進度恢復、資料變更後失效。
- 時序與整合測試：可見性切換、輪詢不重疊、主機切換與舊回應、終端連線關閉。
- 端到端驗證：首次新增至 SSH 成功、錯誤後修正重試、重新整理後接續、既有金鑰路徑。
- 人工介面檢查：首次使用者是否能辨識執行位置、複製回饋、鍵盤操作與長內容版面。
- 優先使用可控制的測試替身或測試主機，保留現有 SSH 與金鑰管理回歸檢查。

## 已確認的補充決策

1. **切換主機的提示**：有活躍終端連線時提示將中斷，可取消；確認後才切換。
2. **只切換左側分頁**：保留同一主機的終端連線，返回主機操作可繼續。
3. **進度保存範圍**：同一瀏覽器保存，每台已加入主機可接續，另保留一筆未建立主機的草稿；不保存密語或私鑰，不要求跨瀏覽器同步。
4. **視覺與小螢幕**：桌面固定左側導覽，小螢幕可收合，採清楚的表單、卡片與步驟指示，驗收包含響應式版面、鍵盤操作與長指令顯示。
