# sshdeck：跨平台本機 SSH 主機管理工具

Status: ready-for-agent

## Problem Statement

使用者需要在自己的電腦管理多台 Linux SSH 主機，以容易辨識的主機別名執行命令、開啟互動終端機及操作已安裝的 Docker。目前缺少整合主機設定、登入金鑰建立、公鑰授權指南與帳號權限檢查的共同入口，必須自行拼接不同工具與設定步驟。

## Solution

提供以 Node.js 執行的本機工具 `sshdeck`，支援 Windows、macOS、Linux。使用者可透過 CLI 操作，或執行 `sshdeck ui` 開啟瀏覽器管理介面；兩個入口共用主機設定、登入金鑰關聯與主機信任紀錄。

使用者先以主機別名新增連線設定，建立帶密語的登入金鑰或選用既有私鑰，再依指南手動安裝公鑰與配置遠端登入帳號權限。驗證成功後，可指定主機別名執行遠端命令或開啟完整互動終端機。Docker 透過通用命令操作；工具提供授權指南及能力檢查。

## User Stories

1. 作為個人使用者，我希望在 Windows、macOS、Linux 使用相同的主要功能，以便切換電腦時維持操作方式。
2. 作為使用者，我希望透過 CLI 開啟瀏覽器管理介面，以便用圖形介面配置主機。
3. 作為使用者，我希望不開啟瀏覽器也能透過 CLI 管理及操作主機，以便直接從命令列工作。
4. 作為使用者，我希望新增具有唯一主機別名的連線設定，以便辨識操作目標。
5. 作為使用者，我希望設定主機位址、SSH 連接埠、登入帳號與登入金鑰，以便連接不同環境。
6. 作為使用者，我希望同一台主機可以有不同帳號的設定，以便選擇執行身分。
7. 作為使用者，我希望隨時修改或刪除主機設定，以便維護動態變動的主機清單。
8. 作為使用者，我希望列出已保存的主機及檢查結果，以便了解設定及最近的可連線情況。
9. 作為使用者，我希望清楚區分歷史檢查結果與目前工作階段，以免將曾經連線成功誤認為持續連線。
10. 作為使用者，我希望按需檢查 SSH 連線，以便找出網路、認證或主機信任問題。
11. 作為使用者，我希望為每組設定建立獨立且帶密語的 Ed25519 金鑰，以便分別管理登入授權。
12. 作為使用者，我希望選用既有私鑰，也能將既有金鑰用於不同設定，以便沿用既有授權。
13. 作為使用者，我希望取得可複製的公鑰與安裝指南，以便透過既有登入管道或控制台完成首次授權。
14. 作為使用者，我希望指南涵蓋帳號建立、公鑰安裝、檔案擁有者及權限，以便建立可用的登入環境。
15. 作為使用者，我希望安裝公鑰後可以驗證登入，以便確認授權配置正確。
16. 作為使用者，我希望首次連線能核對主機指紋，以便確認連入預期主機。
17. 作為使用者，我希望指紋變更時停止連線並要求重新確認，以免靜默接受不同身分的主機。
18. 作為使用者，我希望 CLI 與前端共用信任紀錄，以便維持一致的主機身分判斷。
19. 作為使用者，我希望 CLI 在需要時詢問私鑰密語，以便解鎖加密金鑰。
20. 作為使用者，我希望前端服務期間可暫存解鎖狀態並手動鎖定，以便兼顧連續操作與密語管理。
21. 作為使用者，我希望密語不寫入持久設定且服務停止後清除解鎖狀態，以便避免永久保存解鎖資訊。
22. 作為使用者，我希望依主機別名執行遠端命令並即時查看輸出與結果，以便操作指定主機。
23. 作為使用者，我希望透過 CLI 與前端開啟完整互動終端機，以便操作 shell 與需要互動輸入的程式。
24. 作為使用者，我希望不同主機可以同時執行各自的工作，以免單一工作阻塞其他操作。
25. 作為使用者，我希望每次操作清楚標示主機別名與登入帳號，以便辨識目前操作身分與目標。
26. 作為使用者，我希望終端機關閉時釋放其連線，斷線時顯示原因，以便理解工作階段狀態。
27. 作為使用者，我希望透過遠端 Docker 命令建立、啟動及查看容器，以便完成主機上的容器工作。
28. 作為使用者，我希望取得將信任的登入帳號加入 Docker 群組的指令指南，以便由管理員配置容器操作權限。
29. 作為使用者，我希望檢查登入帳號是否能存取 Docker，以便區分 SSH 登入成功與容器操作權限可用。
30. 作為使用者，我希望工具只提供遠端授權指令及檢查，不自動修改帳號權限，以便自行套用配置。
31. 作為使用者，我希望設定保存於各平台的使用者應用資料目錄，以便重啟後繼續使用。
32. 作為使用者，我希望選用既有私鑰時僅記錄位置，以便保留原有金鑰管理方式。
33. 作為使用者，我希望刪除主機設定不連帶刪除金鑰或遠端授權，以免影響其他使用同一金鑰的設定。
34. 作為使用者，我希望有獨立的金鑰刪除及遠端撤銷指南，以便完整管理授權生命週期。

## Implementation Decisions

### 共用能力與入口

- 本機由 Node.js 程式負責資料保存、金鑰操作與 SSH 連線；CLI 與瀏覽器介面共用這些能力，不能各自維護不同的主機資料或信任判斷。
- 邏輯職責包含主機設定與儲存、金鑰及信任管理、SSH 命令與終端機工作階段、權限指南與診斷、CLI 入口及本機 Web 入口。具體框架、套件及內部拆分由實作決定。
- 本機服務供個人本機使用，瀏覽器透過該服務操作；服務監聽限制於本機，跨來源存取與終端機連線須符合此本機使用邊界。
- 啟動介面須提供可開啟的本機網址；瀏覽器無法自動開啟時仍能讓使用者手動開啟。

### CLI 契約

- `sshdeck ui`：啟動本機服務並開啟管理介面。
- `sshdeck host add <別名>`：新增主機設定；`sshdeck host list`：列出已保存設定。
- `sshdeck host check <別名>`：檢查 SSH 連線及 Docker 可用性，分別呈現結果。
- `host` 指令群必須另提供修改與刪除能力；選項及子指令的細部拼寫可在實作時決定並記錄於使用說明。
- `sshdeck exec <別名> -- <命令>`：在指定受管主機執行命令，串流顯示輸出及結束狀態。命令不得在本機意外執行；命令引用及 shell 解讀規則須有一致的文件與跨平台案例。
- `sshdeck shell <別名>`：開啟 SSH 互動終端機，支援輸入、輸出、終端機尺寸變更及互動程式。
- `sshdeck key create <別名>`：為設定建立登入金鑰；另提供選用既有私鑰及檢視公鑰的流程。
- `sshdeck guide <別名>`：依登入帳號及公鑰產生安裝與權限指南。
- 未知別名、無效參數、認證失敗及連線中斷必須有明確錯誤；CLI 失敗不得回報成功結束狀態。

### 主機資料與狀態

- 每組設定具有唯一主機別名、位址、SSH 連接埠、登入帳號及登入金鑰關聯。同一主機可以用不同別名對應不同帳號。
- CLI 與前端讀寫同一份資料；並行操作不得靜默覆蓋其他設定或造成損毀。
- 列表呈現保存的設定與最近檢查結果，未檢查、成功及失敗必須可區分；歷史檢查不代表即時在線。
- 依操作需要建立連線，不建立供所有主機閒置維持連線的常駐連線池需求。不同主機的命令或終端機互不混用輸出、登入帳號或取消狀態。
- 各平台採用慣用的使用者應用資料目錄；具體目錄及備份方式由使用說明交代。

### 金鑰與信任

- 新建登入金鑰使用帶密語的 Ed25519，預設每組設定獨立建立；建立流程不得覆寫既有私鑰。
- 既有私鑰只保存檔案位置，保留原本密語保護方式；私鑰原始內容不回傳瀏覽器作為設定資料。
- 工具產生的私鑰保存於本機，採用對應平台的使用者檔案存取限制；密語不寫入設定、日誌或命令參數。
- CLI 每次操作需要時解鎖；前端在服務生命週期內暫存解鎖狀態並提供手動鎖定。鎖定後的新連線需重新解鎖，不以移除解鎖快取冒充已終止既有 SSH 工作階段。
- 首次連線顯示指紋並等待信任決策；拒絕則停止連線。指紋改變時停止原操作，使用者核對及更新信任後才能重試，不靜默替換紀錄。
- 主機信任依實際 SSH 端點及主機金鑰辨識，不能單純因修改別名就忽略已知指紋衝突。
- 刪除設定不刪除金鑰、不修改遠端授權；獨立提供本機金鑰刪除及遠端撤銷指南，說明對其他設定的影響。

### 手動授權與 Docker 檢查

- 公鑰由使用者透過既有登入方式或控制台手動加入遠端登入帳號；工具不以密碼登入自動安裝公鑰。
- 指南涵蓋帳號建立、公鑰加入 `authorized_keys`、目錄與檔案的擁有者及權限，不覆蓋既有授權清單。
- Docker 已安裝；指南由具備管理權限的人手動將信任帳號加入 `docker` 群組，說明需重新登入以取得新的群組身分。
- 明確說明一般 Docker 群組具有主機高權限影響，並非每位帳號只管理自己的容器。
- 檢查以目前登入帳號驗證 Docker CLI 與 daemon 存取能力，不僅判定是否在群組名單中；檢查不建立或刪除業務容器、不自動執行提權修復。
- SSH 登入失敗、Docker 缺少、daemon 不可用或權限不足須呈現可判斷的結果；錯誤資訊不足時保留診斷內容，不捏造根因。

### 命令與互動終端機

- CLI 與前端皆提供單次命令及完整互動 shell。每個工作階段清楚標示目標，輸出在工作進行中可見。
- 關閉終端機時結束其 SSH 工作階段並清理本機資源；前端關閉相應頁面或本機服務停止時亦釋放相關連線。
- 斷線顯示原因及結束狀態，重新開啟是新工作階段，不提供恢復原終端機。
- 支援使用者中斷正在操作的命令或關閉工作階段；不能將本機連線結束視為遠端所有衍生程序已停止。
- 長期執行容器使用 Docker 的背景模式；一般遠端程序在斷線後的生命週期由遠端程序決定。

## Testing Decisions

使用者已確認以 CLI 與瀏覽器為主要測試入口，連接可控制的 Linux SSH／Docker 測試環境。測試驗證外部可觀察行為，而非內部函式、框架或資料結構。現有專案沒有應用程式與測試先例；優先建立可重用的端到端測試環境，必要時在資料保存及認證邊界補充整合測試。

驗收情境：

- [x] Windows 與 Linux 實際驗證可啟動 CLI 與本機介面、保存資料並於新程序／服務重新啟動後讀取；macOS 維持相容性目標但本輪未實測、未宣稱驗證。
- [x] CLI 建立／修改後前端可讀取相同資料，前端變更亦可由 CLI 讀取；多程序並行新增設定不互相覆蓋。
- [x] 兩組以上主機設定可依別名使用不同登入帳號；重複及不存在別名有明確錯誤。
- [x] 列表區分未檢查、最近 SSH 成功／失敗及 Docker 狀態，不將歷史結果標示為目前連線。
- [x] 可產生加密 Ed25519 金鑰，正確密語可登入、錯誤密語失敗；既有私鑰可選用且工具不覆寫原檔。
- [x] CLI 與前端提供公鑰及授權指南；隔離測試主機按指南手動加入公鑰後 CLI／UI 均成功登入。
- [x] CLI／前端首次拒絕信任會停止登入／操作；接受後登入。隔離主機 host key 替換後兩入口都阻擋，重新核對後才能重試。
- [x] 密語不寫入設定、registry 或檢查狀態；前端 lock／服務重啟後新 SSH 工作階段需要重新解鎖，既有 session 不因 lock 假裝終止。
- [x] CLI／UI 遠端命令即時串流 stdout／stderr，呈現 exit status，並辨識認證錯誤、非零狀態、取消及連線中斷。
- [x] 遠端命令空白、引號、Unicode 及特殊字元依文件規則在遠端 shell 解讀；Windows 與 Linux 實測，命令不會在本機 shell 執行。macOS 未測。
- [x] CLI／前端 PTY 支援互動輸入、尺寸變更及互動 shell；CLI 還原 raw mode，關閉／服務停止釋放對應 session。
- [x] 兩個不同登入帳號與 host alias 可同時運作且輸入／輸出／取消隔離；關閉後重新開啟為全新 shell。
- [x] SSH 成功但 Docker socket 權限不足可明確辨識；在專用 SSH fixture 套用 Docker 群組並重新登入後，CLI／UI 均回報可用。
- [x] 使用遠端命令建立、啟動、查看唯一命名測試容器並精確清理；`host check` Docker 能力檢查本身不建立容器。
- [x] 刪除主機設定不連帶刪除共用金鑰或撤銷遠端公鑰；managed key 可獨立解除關聯／刪除，並提供手動撤銷指南。
- [x] 本機 HTTP／WebSocket 入口遵守 loopback Host／Origin 邊界；不可信來源被拒，瀏覽器關閉或服務停止會清理對應連線。macOS 未測。

Windows 與 Linux 驗證須記錄實際平台及結果。macOS 是相容性目標，但依使用者決定，本輪不測試 macOS；不得將其標示為已驗證。測試環境使用專用帳號、金鑰及容器，不依賴使用者的實際主機或私鑰。

## Out of Scope

- 多人登入、共用託管管理平台與獨立桌面應用程式。
- Windows 遠端主機、SSH 跳板機及工具自行建立 VPN。
- 無人值守排程、系統 SSH agent 共用解鎖及長期保存密語。
- 一鍵將同一命令批次執行於多台主機。
- Docker 安裝、專用容器管理畫面、Rootless Docker 與受限指令權限模型。
- 自動建立遠端帳號、自動安裝公鑰或自動修改遠端權限。
- 持久終端機、斷線續接與恢復原工作階段。
- 發布到公開套件平台及確認 `sshdeck` 套件名稱可用性。
