# 01：跨平台入口與主機設定管理

Status: ready-for-agent
Blocked by: None

## What to build

使用者可以啟動 `sshdeck` CLI 或透過 `sshdeck ui` 開啟本機瀏覽器介面，在兩端新增、查看、修改及刪除受管主機設定，重啟後仍能使用相同資料。這張票建立第一條可展示的完整操作流程，包含必要的應用程式初始化及技術選型。

規格：[sshdeck spec](../spec.md)。涵蓋 User Stories 1–9、25、31、33 的主機設定部分。

## Acceptance criteria

- [ ] Node.js CLI 可啟動並提供使用說明；記錄 Node.js 最低版本、套件管理器及執行方式，設計支援 Windows、macOS、Linux。
- [ ] `sshdeck ui` 啟動本機服務並開啟瀏覽器；無法自動開啟時顯示可手動開啟的網址，服務可正常停止。
- [ ] CLI 與前端均可新增、列出、修改、刪除主機設定，包含唯一主機別名、位址、SSH 連接埠、登入帳號與可後續綁定的登入金鑰關聯。
- [ ] 可保存至少兩組主機設定，同一實體主機可對應不同登入帳號；重複別名、無效輸入與未知別名有明確錯誤，CLI 失敗回傳非零結束狀態。
- [ ] CLI 與前端雙向讀取相同變更，資料存於各平台慣用的使用者應用資料目錄；重啟後資料仍存在，並行寫入不損毀或靜默覆蓋其他變更。
- [ ] 主機列表呈現未檢查狀態，不將已保存設定視為已連線；主機操作清楚標示別名與登入帳號。
- [ ] 刪除設定僅移除設定，不連帶刪除登入金鑰或執行遠端撤銷。
- [ ] 本機 Web 服務僅監聽本機，存取與跨來源處理符合個人本機操作邊界。
- [ ] 透過 CLI 及瀏覽器驗證完整管理流程，另驗證並行保存與重啟讀取；記錄實際執行平台，不把未測平台視為通過。

## Verification notes

以外部入口驗證行為。此票不要求 SSH 實際連線；不得以假的成功結果冒充連線能力。三平台完整整合證據由 07 彙整。
