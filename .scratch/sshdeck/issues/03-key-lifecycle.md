# 03：金鑰建立與授權生命週期

Status: ready-for-agent
Blocked by: 02

## What to build

使用者在 CLI 與前端建立新登入金鑰，取得公鑰與遠端授權指南，手動套用後完成 SSH 驗證；另能獨立管理本機金鑰刪除及遠端公鑰撤銷。

前置：02「既有金鑰登入與主機信任」。規格：[sshdeck spec](../spec.md)。涵蓋 User Stories 11、13–15、30、33–34。

## Acceptance criteria

- [ ] `sshdeck key create <別名>` 與前端皆可建立帶密語的 Ed25519 金鑰，預設每組設定使用獨立金鑰，建立後可供該設定登入。
- [ ] 建立過程不覆寫既有金鑰，工具私鑰保存於本機應用資料目錄，依本機平台限制檔案存取；失敗時不留下被當作可用金鑰的殘缺資料。
- [ ] CLI 與前端皆可檢視及複製公鑰；密語與私鑰不作為可檢視設定內容輸出。
- [ ] `sshdeck guide <別名>` 與前端依登入帳號及公鑰提供手動授權指南，涵蓋帳號建立、加入 `authorized_keys`、目錄／檔案擁有者及權限，保留既有公鑰。
- [ ] 指南說明使用者須透過既有登入管道或控制台套用；工具不自動登入安裝公鑰或修改帳號權限。
- [ ] 使用新產生的金鑰依指南手動配置測試主機後，可從 CLI 與前端成功驗證登入；錯誤密語仍會失敗。
- [ ] 刪除主機設定不移除本機金鑰或遠端授權；另提供明確的本機金鑰刪除操作及遠端撤銷指南，說明共享金鑰所影響的設定。
- [ ] 管理既有私鑰時維持只記錄位置的語意，解除關聯不刪除使用者原始私鑰；工具管理金鑰的實際刪除須與解除關聯清楚區分。
- [ ] 驗證生成、手動授權、登入、保留其他公鑰、共享金鑰及獨立刪除／撤銷流程，記錄平台相關檔案保護的驗證結果。

## Verification notes

指南應可在文件明示的 Linux 測試環境直接套用，說明必要的管理權限。Docker 群組授權指南由 06 補入同一使用者流程。
