# 02：既有金鑰登入與主機信任

Status: ready-for-agent
Blocked by: 01

## What to build

使用者在 CLI 與前端選用既有私鑰，解鎖後核對受管主機指紋並測試 SSH 登入。兩端共用信任紀錄與最近檢查結果，提供後續命令與終端機可重用的連線能力。

前置：01「跨平台入口與主機設定管理」。規格：[sshdeck spec](../spec.md)。涵蓋 User Stories 8–10、12、15–21、32。

## Acceptance criteria

- [ ] CLI 與前端可為主機設定選用本機既有私鑰，只保存檔案位置、不覆寫或複製原始私鑰；可讓不同設定選用同一金鑰。
- [ ] 加密私鑰沿用原密語保護；CLI 每次操作需要時詢問密語，錯誤密語、檔案不存在或不支援格式有明確失敗結果。
- [ ] 前端在本機服務期間暫存解鎖狀態，提供手動鎖定；鎖定或服務重啟後的新連線需重新解鎖，密語不寫入持久設定、日誌或命令參數，私鑰內容不回傳瀏覽器。
- [ ] 首次連線顯示主機指紋供核對；拒絕信任時停止登入及後續操作，接受後保存信任紀錄。
- [ ] 主機指紋變更時停止原操作；使用者重新核對並更新信任後才可重試，不靜默替換。修改別名不能繞過同一端點的指紋衝突。
- [ ] CLI 與前端共用信任判斷，支援直接連接指定 SSH 位址及連接埠。
- [ ] `host check` 及前端檢查可驗證 SSH 登入，呈現最近檢查結果並區分未檢查、成功、失敗；檢查結束釋放連線，不把歷史成功顯示為目前在線。
- [ ] 網路失敗、認證失敗及指紋拒絕／衝突有可辨識的錯誤，CLI 失敗不回報成功結束狀態。
- [ ] 使用可控制的 Linux SSH 測試環境，經 CLI 與瀏覽器驗證成功登入、錯誤密語、首次拒絕、指紋替換、共用信任及手動鎖定／重啟流程。

## Verification notes

測試使用專用帳號與金鑰。此票的 `host check` 先交付 SSH 檢查，Docker 檢查由 06 加入，不預先回報 Docker 可用。共用認證與信任規則須適用後續所有 SSH 操作。
