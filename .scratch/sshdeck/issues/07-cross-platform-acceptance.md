# 07：三平台整合驗收與使用文件

Status: ready-for-agent
Blocked by: 03, 04, 05, 06

## What to build

使用者可依完整文件在 Windows、macOS、Linux 啟動 sshdeck，完成主機設定、金鑰授權、SSH 與 Docker 檢查、遠端命令及互動終端機操作。本票整合已完成能力、修正跨平台整合問題，提供規格全部驗收項目的可追溯證據。

前置：03「金鑰建立與授權生命週期」、04「依主機別名執行遠端命令」、05「CLI 與瀏覽器互動終端機」、06「Docker 權限指南與操作驗證」。規格：[sshdeck spec](../spec.md)。整體涵蓋 User Stories 1–34，補足跨平台與完整使用流程驗收。

## Acceptance criteria

- [ ] 文件完整說明本機安裝／執行前提、Node.js 支援版本、CLI 指令、啟動及停止介面、資料位置與備份方式；不依賴公開套件發布才能使用。
- [ ] 文件涵蓋兩種金鑰來源、主機指紋核對、手動公鑰授權、Docker 群組授權與檢查、命令引用規則、互動終端機及金鑰撤銷流程。
- [ ] Windows、macOS、Linux 均實際驗證 CLI／介面啟動、資料保存與重啟讀取、金鑰檔案存取限制、遠端命令引用及互動終端機行為，記錄平台、環境與結果。
- [ ] 以可控制的 Linux SSH／Docker 環境完成端到端使用流程，包含兩台主機同時操作、登入帳號區分及 Docker 容器建立／啟動／查看。
- [ ] 整合驗證資料雙向一致與並行保存、共用信任、指紋替換阻擋、密語不持久保存、鎖定／服務重啟後重新解鎖及刪除設定不影響金鑰／遠端授權。
- [ ] 整合驗證命令失敗、斷線、取消、終端機關閉及本機服務停止，輸出與生命週期不跨主機干擾，瀏覽器入口符合本機存取邊界。
- [ ] 對照 spec 的全部驗收情境建立證據對應，重用仍有效的前置票測試；必要整合修正完成後驗證受影響範圍。
- [ ] 更新 spec 與各票的驗收 checklist 時僅勾選有證據的項目；任何未執行平台或未通過項目保持未勾選並記錄阻礙，不能宣稱全數通過。
- [ ] 測試使用專用帳號、金鑰及容器，不使用使用者的真實私鑰；流程清理測試資源，不以內部函式測試取代外部行為驗收。

## Verification notes

此票不是將所有測試延後才執行：前置票各自交付必要測試，本票負責平台矩陣、整體旅程與驗收證據整合。若執行環境不足以驗證三平台，明確記錄阻礙，不將模擬平台路徑測試視為實機驗證。
